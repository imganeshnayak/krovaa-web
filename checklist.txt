**ShipRocket Integration Layer** (Key Decision: Per-Seller vs. Centralized)
- [ ] **Option A (Recommended for marketplace)**: Centralized account with seller sub-accounts
  - One master ShipRocket account for your platform
  - Each seller has a sub-account or channel within it
  - Easier to manage, single credential set
  - ShipRocket supports channel/warehouse management

- [ ] **Option B**: Individual seller accounts
  - Sellers create own ShipRocket accounts
  - You integrate via their credentials
  - More control for sellers, higher complexity
  - Seller must provide API key

  - Update status → return_initiated → returned

### **5. CRITICAL IMPLEMENTATION DECISIONS**

| Decision | Impact | Recommendation |
|----------|--------|-----------------|
| **ShipRocket account model** | Seller experience, cost, complexity | Centralized with channels (easier) |
| **Label printing** | Seller workflow, time | Direct thermal printer integration via browser API |
| **Webhook vs. Polling** | Real-time accuracy, server load | Use webhooks + poll every 6 hours as fallback |
| **Multi-packaging** | Seller complexity | Disallow (1 shipment = 1 order) initially |
| **Pickup scheduling** | Seller convenience | Auto-request pickup when "Mark packed" is clicked |
| **Return shipments** | Complexity, cost | Route through separate ShipRocket RTO flow |
| **Seller payout timing** | Trust, cash flow | After delivery confirmed (not at order place) |
